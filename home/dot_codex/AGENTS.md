# 后端测试规范
作用域：本节规则仅在 Go 后端测试相关任务中生效（如 `go test`、测试文件编写/修改、测试执行与清理）；非测试任务忽略本节。

1. 运行测试前必须先实际检查测试是否依赖远程服务（如 DB、VectorDB、远程容器内工具链）。
   检查方式优先包括：
   - 查看测试初始化代码与 `testutil` 依赖
   - 使用 `go test -run '^$'` 做最小范围编译检查
   - 必要时使用 `go test -run <具体用例>` 做最小范围预判
2. 如果确认测试依赖远程服务、远程数据库、或仅在远程环境中可用的工具链，则后续测试执行必须在本机交互式 shell 进入远程环境后完成，不能在沙箱环境中直接执行，也不能使用一次性非交互命
令直接远程执行测试。
3. 如果确认测试为纯本地逻辑验证，且不依赖远程服务，则允许先在本地执行最小范围测试；需要扩大范围或环境不一致时，再切换到远程环境。
4. 默认最小测试范围，优先使用 `-run` 指定单测，避免直接运行大范围测试。
5. 涉及数据库创建或修改记录的测试，必须注册 `t.Cleanup` 并清理数据，避免污染真实测试库。
6. 测试用户、设备、数据库等环境信息，优先在 `testutil` 包中搜索并复用。
7. 新后端测试文件统一放在当前模块的 `tests/` 目录下。

## 远程 shell 进入方式
当第 2 条命中时，必须按以下方式执行：

1. 必须先在项目根目录启动本机交互式 shell：
   `lzc-cli project exec --workdir /lzcapp/cache/project-mirror/backend`
2. 进入远程环境后，再在该 shell 内执行 `go test`、`go test -run ...` 等测试命令。
3. 不允许用 `lzc-cli project exec ... -- sh -lc 'go test ...'` 这类一次性非交互方式替代上述流程。

## 代码编写与重构规范
核心原则：高内聚、低耦合。
每次代码变动都应提升模块独立性与清晰度。
1. 当模块涉及大量修改时，保留核心流程。
2. 将辅助结构体与通用能力抽离并下沉到新包。
3. 新包优先放在当前目录的子目录中。
4. 禁止新增任何非 err 的 nil 兜底分支（包含结构体字段、方法接收者、局部变量、返回对象与调用方判空）；若确需容错，必须先说明理由并经用户确认。
